✅ Auth Flow Summary for Frontend (Cookies + Firebase + DRF)
We're using Firebase Auth on the frontend, but relying on Django to manage session-like behavior via secure HTTP-only cookies. Here’s how each step works:

🔐 1. Login (POST /api/v1/auth/login/)
Request Body:

json
{
  "email": "user@example.com",
  "password": "password123"
}

On Success:
Backend authenticates with Firebase, then authenticates Django user

Returns:
json
{
  "success": true,
  "user": {
    "id": 1,
    "email": "user@example.com",
    "firstName": "...",
    "lastName": "..."
  }
}
And sets these cookies: firebase_token (Firebase ID token, short-lived), firebase_refresh (Firebase refresh token, long-lived)
Cookies are:HttpOnly, Secure, and SameSite=Lax
Not visible in JavaScript, but sent automatically with same-origin requests

🟢 2. Status Check (GET /api/v1/auth/status/)
Requires no body
Cookie firebase_token must be present (sent automatically by browser)
Returns:
json
{
  "authenticated": true,
  "user": {
    "id": 1,
    "email": "user@example.com",
    "firstName": "...",
    "lastName": "..."
  }
}
If cookie is missing or invalid:

json
{
  "authenticated": false
}
🔁 3. Refresh Token (POST /api/v1/auth/refresh/)
Reads firebase_refresh cookie, contacts Firebase to refresh ID token

Sets new cookies: New firebase_token, Optionally new firebase_refresh
Returns:
json
{
  "success": true
}
⚠️ No need to read tokens from body — the browser will handle it via cookies

🚪 4. Logout (POST /api/v1/auth/logout/)
Deletes both firebase_token and firebase_refresh cookies

Returns:
json
{
  "success": true
}
After logout, /auth/status/ will return:
json
{
  "authenticated": false
}

⚠️ No need to read tokens from body — the browser will handle it via cookies

🚪 4. Logout (POST /api/v1/auth/logout/)
Deletes both firebase_token and firebase_refresh cookies

Returns:
json
{
  "success": true
}

After logout, /auth/status/ will return:

json
{
  "authenticated": false
}

🧭 What Frontend Needs to Handle
Task	                       Frontend Behavior
Logging in	            Send email/password to /auth/login/
Persisting session	    Let browser manage cookies (no need to store tokens)
Checking login	        Call /auth/status/ and handle authenticated vs not
Refreshing token	    Optionally call /auth/refresh/ periodically (e.g. on 401 or every 30 mins)
Logging out	            Call /auth/logout/ and clear any local user data

🛑 CORS & Cookie Considerations
Make sure:
Frontend and backend share same top-level domain (e.g. localhost and localhost)

Frontend sends credentials:

fetch("/api/v1/auth/status/", {
  method: "GET",
  credentials: "include"  // <-- required!
});
Backend allows CORS with credentials (set CORS_ALLOW_CREDENTIALS = True in Django)

Essentials-
1.On login, start a background interval to call /auth/refresh/ every ~55 minutes
2.On 401 responses, try to refresh once, then retry the failed request
3.Use credentials: "include" in all API calls to send cookies
4.Don't try to manage firebase_token manually in frontend JS — let cookies handle it
